# 仓库定时同步系统 · 需求规格说明

本文由 `docs/需求文档.md` 整理而成。原始记录保留不动。文中「默认」是整理时补上的可实施方案；若与你的意图不一致，以第 10 节的待确认项为准，改完后再进入开发。

## 1. 产品目标

做一个单管理员使用的仓库定时同步系统：从 Gitee 或 GitHub 拉取上游，在本机保留镜像，并按配置把内容同步到其他目标。管理员可以查看仓库、检查与上游的差异、查看同步日志，并用已启用的 AI 厂商为每个仓库生成概要介绍。

界面语言为中文。调度计算和界面上的时间一律使用 `Asia/Shanghai`。数据库内部时间存 UTC，展示时再换算。

## 2. 角色与范围

系统只有一个管理员。打开系统必须先用密码登录，登录后可以修改密码。

本期要做：

- 按上游地址添加仓库，添加成功后立即同步一次
- 定时同步，也支持手动检测差异和手动立即同步
- 仓库列表、详情、删除
- 同步日志与保留期
- AI 概要
- 多主题切换
- 平台凭证与 WebDAV 连接信息

本期不做：

- 多用户、注册、角色权限
- 在线编辑仓库文件或在网页里产生新提交
- 用 AI 生成或编辑主题
- 运行时请求 tweakcn.com

## 3. 同步模型

一次同步的顺序固定为：

1. 从上游拉取最新 Git 数据到本地镜像。
2. 本地镜像更新成功后，再按该仓库勾选的目标分别同步。
3. 某个目标失败不影响其他目标；每个目标单独记录成功、失败或跳过。

上游只能是 Gitee 或 GitHub。第一版只接受 HTTPS 仓库地址（可带或不带 `.git`）。系统保存前做规范化，并用规范化后的上游地址防止重复添加。

目标分两类：

| 目标 | 是否必选 | 同步方式 |
| --- | --- | --- |
| 本地存储 | 必选 | 本机保存一份 Git 镜像，包含全部分支和标签 |
| Gitee | 可选 | 本地镜像更新后，向指定的 Gitee 空仓库或已有仓库推送镜像 |
| GitHub | 可选 | 与 Gitee 相同，推送目标改为 GitHub |
| WebDAV | 可选 | 上传默认分支的工作区文件，保留目录结构，不上传 `.git` |

一个仓库可以同时勾选多个可选目标。Git 推送使用镜像方式：目标远程跟随上游的分支和标签。本地镜像不接受网页侧的新提交。

同一仓库不会并行同步。上一次还在执行时，新的定时触发记为「跳过」。不同仓库可以并行，默认同时 2 个，可在设置中调整。

网络类失败自动重试，最多 3 次。凭证错误、仓库不存在、目标拒绝推送不再重试。

### 3.1 差异检测

差异检测只比较，不修改本地或任何目标。比较对象是本地镜像与上游的分支和标签。结果分为：

- 一致
- 本地落后于上游
- 双方历史分叉
- 检测失败

列表和详情展示最近一次检测结果与检测时间。检测到落后或分叉后，管理员可以手动立即同步。

### 3.2 凭证

公开仓库拉取可以不填凭证。私有仓库，以及向 Gitee / GitHub 推送，必须配置对应平台的个人访问令牌。

- Gitee、GitHub：每个平台保存一套令牌，供该平台的拉取和推送共用
- WebDAV：保存服务器地址、用户名和密码
- 密钥加密后存放，界面只显示是否已配置，不回显原文
- 设置页提供连接测试

第一版不支持 SSH 地址和部署密钥。

## 4. 功能需求

### 4.1 登录与密码

- 未登录只能进入登录页
- 首次启动使用环境变量中的初始密码创建管理员
- 登录后可修改密码；修改成功后其他会话失效，当前会话保持
- 忘记密码时，通过同一环境变量重置，不提供邮箱找回
- 密码只保存慢哈希，连续登录失败需要限流

### 4.2 添加仓库

管理员提交上游 HTTPS 地址，并填写：

- 显示名称，默认识别上游的拥有者与仓库名
- 调度（见 4.5）
- 可选目标：Gitee 仓库地址、GitHub 仓库地址、WebDAV 目录，至少零个、可以多个
- 使用哪套已保存凭证

系统先校验地址可访问，再创建记录并立刻执行首次同步。首次同步的上游拉取失败时，不保留这条仓库记录，并展示错误摘要。上游成功、某个目标失败时，仓库保留，目标状态记为失败。

添加完成后自动生成一次概要。生成失败只提示，不影响仓库已添加。

### 4.3 仓库列表

列表支持网格和列表两种展示，选择记在本机。两种展示使用同一套数据和筛选条件。

每条至少显示：名称、上游平台、概要的第一行、最近同步结果、最近差异结果、下次执行时间。

支持：

- 按名称和上游地址搜索
- 按上游平台、同步状态、差异结果筛选
- 按名称或最近同步时间排序
- 空列表时说明如何添加

同步状态至少包括：从未同步、同步中、成功、失败、跳过。

### 4.4 仓库详情

详情页展示：

- 名称、概要、上游地址、已配置目标
- 调度与下次执行时间
- 最近一次同步和最近一次差异检测
- 只读内容：默认分支的目录树、README 渲染、最近 20 条提交
- 体积、默认分支、分支数、标签数

可执行的操作：立即检测差异、立即同步、重新生成概要、编辑、删除。

编辑可以修改名称、调度、可选目标和启用状态，不能把一条记录改绑到另一个上游。需要换上游时删除后重新添加。调度可以暂停；暂停后不再定时执行，仍可手动同步。

删除前需要确认。删除只移除本系统记录、本地镜像，以及本系统写到 WebDAV 的对应目录。不删除 Gitee 或 GitHub 上的远程仓库。正在同步时不允许删除。

### 4.5 调度

每个仓库一条调度。可选：

- 每天的某个时分
- 每周的星期几和时分
- 每月的某日和时分
- 五段 Cron：分、时、日、月、周

精度到分钟，不提供秒。Cron 输入需校验，非法表达式不能保存。每月日期若当月不存在，则在该月最后一天的同一时分执行。

### 4.6 同步日志

每次同步写一条日志，字段包括：

- 开始时间、结束时间、触发方式（首次添加、定时、手动）
- 上游地址和上游结果
- 每个目标的名称、类型、结果和错误摘要
- 整次任务的最终状态

日志页面可按仓库、状态、时间筛选。详情能看到上述字段。

保留期默认 7 天，可在设置中修改，允许范围 1 至 180 天。超过保留期的日志由系统自动清理。180 天对应设置里的最长 6 个月。

### 4.7 AI 概要

可以保存多个 AI 厂商，任意时刻最多一个处于启用。允许全部停用；停用时同步仍正常，只是不再自动生成概要。

每个厂商包含：名称、OpenAI 兼容的接口地址、密钥、模型名。设置页可以测试当前启用的厂商。

概要是一段中文介绍，约 150 至 300 字。生成时只提交 README、主要语言和最近提交说明。结果保存在仓库上，详情页可以手改，也可以重新生成。手改后的内容在下次手动重新生成前保持不变。

### 4.8 设置

设置页集中管理：

- 修改密码
- 日志保留天数
- 同步并行数
- Gitee、GitHub、WebDAV 凭证
- AI 厂商
- 主题入口（与顶栏选择器共用同一套偏好）

## 5. 界面与主题

视觉基于 shadcn/ui 和 Tailwind CSS。主题预设与显示模式是两个独立选项：

- 预设：内置 tweakcn 官方主题。具体名单以开发时锁定的上游版本为准，不在运行时写死数量
- 模式：浅色、深色、跟随系统

顶栏提供主题选择器，交互对齐 tweakcn 的主题列表，而不是它的 AI 生成页：

- 可搜索主题名称
- 每项展示名称和色板，并标出当前项
- 可以随机换一个预设；随机结果保存实际主题，不保存「随机」这个状态
- 可以切换浅色、深色、跟随系统
- 选择后立即作用于全站，刷新后仍然保持
- 桌面端用弹出面板，窄屏用抽屉；键盘可以上下选择、回车确认、Esc 关闭

主题数据随前端构建产物提供，启动时不访问 tweakcn 网络。预设遵循 Apache-2.0，分发时带上许可证和来源说明。首屏在绘制前应用已保存主题，避免先闪默认色再切换。

## 6. 技术与工程约束

前后端分离。

后端：

- 代码放在 `backend/`
- Python，使用 uv 管理环境和依赖
- 提供 JSON API
- 数据访问层同时支持 SQLite、PostgreSQL、MySQL，默认 SQLite
- 数据库类型和连接信息通过配置切换，业务代码不绑定某一种数据库
- 默认技术选型为 FastAPI 与 SQLAlchemy。若实现时更换，需仍满足上面的接口和数据库要求

前端：

- 代码放在 `frontend/`
- Vite、React、shadcn/ui、Tailwind CSS
- 通过后端 API 读写数据，不直接访问数据库

根目录提供 Makefile。执行 `make` 或 `make dev` 时同时启动前端和后端。默认前端 `http://127.0.0.1:5173`，后端 `http://127.0.0.1:8000`，端口可通过环境变量修改。

本地镜像目录、数据库文件和加密密钥路径均可配置，并与源码目录分开。

## 7. 文档交付

实现过程中在 `docs/` 维护下面两份文档，并随代码变更更新：

1. `docs/架构说明.md`：前后端结构、框架、主要组件、数据存储和主题方案
2. `docs/功能说明.md`：当前已经可用的功能、尚未完成的范围、使用方式

未实现的能力写在功能说明的未完成部分，不写成已经可用。

## 8. 验收标准

- 使用初始密码可以登录，登录后可以修改密码，未登录不能访问仓库和设置
- 添加一个可访问的 GitHub 或 Gitee HTTPS 仓库后，本地出现镜像，列表能看到该仓库
- 每天、每周、每月和合法 Cron 都会在上海时区的预期分钟触发；非法 Cron 不能保存
- 同一仓库同步未结束时，下一次定时触发记为跳过
- 详情页可以浏览默认分支目录和 README，并看到最近提交
- 手动检测能区分一致、落后、分叉和失败；手动同步会再次拉取上游并更新已勾选目标
- Gitee、GitHub、WebDAV 目标的成功和失败在同一次日志里分开显示
- 日志默认保留 7 天，设置超过 180 天时拒绝保存，过期日志会被清理
- 可以保存多个 AI 厂商且只有一个启用；概要生成失败时仓库同步仍算成功
- 顶栏可以搜索并切换 tweakcn 主题和显示模式，刷新后选择仍在
- `make dev` 能同时把前端和后端跑起来
- 默认 SQLite 可完成上述流程；PostgreSQL 与 MySQL 至少完成一次空库启动和仓库的增删查

## 9. 配置项

| 配置 | 默认 |
| --- | --- |
| 时区 | Asia/Shanghai |
| 数据库 | SQLite |
| 日志保留 | 7 天，允许 1–180 天 |
| 同步并行数 | 2 |
| 单仓库失败重试 | 网络错误最多 3 次 |
| 概要长度 | 150–300 字中文 |
| 初始管理员密码 | 由环境变量提供 |

## 10. 待确认项

下列默认已经写进上文。确认或改掉之后，再按本文开发。

1. WebDAV 只上传默认分支工作区，不上传 `.git`，也不删除 Gitee/GitHub 远程仓库。
2. 第一版纳入私有仓库，使用每个平台一套访问令牌。
3. 本地镜像保留全部分支和标签；网页内容只展示默认分支。
4. 概要在添加成功后自动生成，平时不同步更新，除非管理员重新生成。
5. 单管理员，忘记密码只通过环境变量重置。
6. 后端默认使用 FastAPI 与 SQLAlchemy。
